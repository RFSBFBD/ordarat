## المشكلة الأكبر (حاجز تشغيلي لا عيب كود): مسار /api على النشر لا يوصل JSON
كل مسارات `/api/*` على ordarat.vercel.app ترجع صفحة الـ SPA (HTML) وليس JSON —
هذا خطأ توجيه/ربط مؤكد بالفحص المباشر. ملف vercel.json في المستودع يستثني
`/api/` من إعادة التوجيه لصفحة الـSPA، فلو كان النشر على أحدث إعداد لكان `/api/*`
يرجع 404 بدل HTML؛ إذن إعداد مشروع Vercel المنشور أقدم من المستودع أو مختلف عنه،
وفي الحالتين لا يوجد ما يقدّم استجابة JSON للـ API على النطاق. لازم نشر الـ
backend وربطه (الخطوات في DEPLOYMENT.md) وإلا لن تعمل المتاجر ولا الدخول ولا الطلبات.
إعداد Firebase متسق: الواجهة وbackend/.env.example وconfig/services.php كلها على
`planning-with-ai-d25ac`؛ صحّحنا في هذه النسخة سطر DEPLOYMENT.md والقيمة الاحتياطية
في FirebaseAuthService اللذين كانا يذكران `ordarat-qena`.

## ما اتغير في الكود (frontend فقط)
- **نظام تحميل جديد**: شاشة اللوجو الكاملة للانتقالات البطيئة فقط (بتأخير 250ms ضد الفليكر)
  وللعمليات الحاسمة (تأكيد الطلب)؛ طلبات الـ API العادية تظهر شريط تقدم رفيع أعلى الصفحة
  بدل تعتيم الشاشة كلها مع كل طلب.
- **timeout 20 ثانية** لكل طلبات الـ API حتى لا تعلق الصفحة بلا نهاية عند موت السيرفر.
- **فشل تحميل route**: صفحة خطأ واضحة مع زر إعادة تحميل بدل صفحة فاضية (NavigationError).
- **دخول Google**: لو جوجل نجح والسيرفر مجاوبش، تظهر رسالة صريحة مع زر «حاول تاني»
  بدل الانتقال الصامت لصفحة رئيسية نص-مسجلة، وتنبيه ثابت أعلى الموقع مع إعادة المحاولة.
- **تتبع الطلب**: التحديث التلقائي كل 30 ثانية أصبح صامتًا (بدون مؤشرات تحميل)،
  وفشل تحديث خلفي لا يمسح شاشة الطلب السليمة.
- **skeleton loaders** لكروت المتاجر أثناء التحميل + حركة دخول ناعمة لكل صفحة
  ولمسات ديناميكية للرئيسية (شريط مميزات: كاش عند الاستلام / توصيل من المحل / جوه قنا).
- **هندسة الكود**: توحيد خط أنابيب الاستجابة في ApiService (53 موضع تكرار أصبحت
  `unwrap()` واحدة مع timeout وتحويل الأخطاء) وحذف `TranslationService` غير المستخدمة.
- كل استدعاءات الـ API في الواجهة لها routes مقابلة في backend/routes/api.php (تم التحقق آليًا).
