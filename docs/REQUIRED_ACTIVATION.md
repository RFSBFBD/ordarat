# خطوات التفعيل الإجبارية — اقرأ هذا الملف قبل أي تشغيل

هذه النسخة (أحدث من v3) لن يشتغل فيها تسجيل الدخول ولا الطلبات على الرابط المباشر
إلا بعد تنفيذ الخطوات الأربعة التالية **بالترتيب**. الكود جاهز ومُختبر محليًا
(96 اختبار باك إند + 43 اختبار فرونت إند)، لكن التفعيل يعتمد على حساباتك أنت
(Firebase وNeon وسيرفر الباك إند)، ولا يمكن لأحد غيرك إتمامه.

---

## 1) تفعيل Firebase (بدونه زر تسجيل الدخول يظل معطّلًا)

1. افتح <https://console.firebase.google.com> وسجّل بحساب جوجل بتاعك.
2. أنشئ مشروعًا جديدًا باسم مثل `ordarat-qena` (أو استخدم مشروعك الحالي).
3. من **Build → Authentication → Sign-in method** فعّل مزوّد **Google** فقط.
   (البريد/كلمة المرور لم تعد مدعومة في المنصة — الدخول كله بزر جوجل واحد.)
4. من **Authentication → Settings → Authorized domains** أضف دومين موقعك، مثل:
   - `ordarat.vercel.app`
   - أي دومين مخصص تستخدمه لاحقًا.
5. من **Project settings → General → Your apps** أنشئ تطبيق Web (أيقونة `</>`)
   وانسخ قيم الإعدادات التالية:
   - `apiKey`
   - `authDomain`
   - `projectId`
   - `appId`
6. ضع هذه القيم في ملفي البيئة بالفرونت إند:
   - `frontend/src/environments/environment.ts`
   - `frontend/src/environments/environment.prod.ts`

   مكان العبارات `FIREBASE_WEB_API_KEY_PLACEHOLDER` و`FIREBASE_WEB_APP_ID_PLACEHOLDER`.
   هذه القيم ليست سرّية بطبيعتها (تظهر في المتصفح لأي زائر)، لكن لا تضع أي
   مفاتيح Admin/Service Account في الفرونت إند أبدًا.

### إعداد الباك إند للتحقق من جوجل

7. من **Project settings → Service accounts** اضغط **Generate new private key**
   واحفظ ملف JSON على جهازك (هذا سرّي فعلًا — لا يدخل Git ولا ZIP).
8. في سيرفر الباك إند (خطوة 3 بالأسفل) اضبط متغيرات البيئة:
   - `FIREBASE_PROJECT_ID=` نفس `projectId`
   - `FIREBASE_CREDENTIALS=` المسار الكامل لملف الـ JSON على السيرفر.
9. عرّف الأدمن الأساسي في متغير البيئة `ADMIN_EMAILS` — قائمة إيميلات جوجل
   مفصولة بفواصل، مثل:
   `ADMIN_EMAILS=you@gmail.com,second@gmail.com`
   أي حساب يدخل بجوجل بإيميل مذكور هنا **وبريد موثّق لدى جوجل** يحصل على صلاحية
   الأدمن من السيرفر مباشرة. لا توجد طريقة لمنح الصلاحية من الواجهة.

> التحقق من هوية كل مستخدم يتم في الباك إند من توقيع توكن Firebase والبريد
> الموثّق (`email_verified`). أي قيمة ترسلها الواجهة (إيميل/دور) لا تُقبل كدليل.

## 2) نقل قاعدة البيانات إلى Neon Postgres

1. افتح <https://neon.tech> وأنشئ مشروعًا جديدًا (الخطة المجانية تكفي للبداية).
2. انسخ رابط الاتصال (Connection string) الذي يبدأ بـ `postgresql://`.
3. في ملف `.env` الخاص بالباك إند على السيرفر اضبط:

   ```
   DB_CONNECTION=pgsql
   DB_URL=postgresql://...الرابط الكامل من Neon...
   ```

4. نفّذ المايجريشنز على السيرفر:

   ```bash
   cd backend
   php artisan migrate --force
   ```

   هذا ينشئ كل الجداول، بما فيها جدول `merchant_applications` الجديد (طلبات
   انضمام أصحاب الأنشطة) وحقول ملف العميل (العنوان والإحداثيات وحالة الإكمال).

5. لا يوجد أي حذف لبيانات قديمة: التوحيد على دخول جوجل يربط الحسابات الموجودة
   بنفس البريد الموثّق تلقائيًا.

## 3) نشر الباك إند (سبب تعطّل الموقع المباشر حاليًا)

المشكلة المؤكدة الآن: `https://ordarat.vercel.app/api/*` يعيد صفحة الموقع نفسها
(HTML) وليس ردود API — أي أن Vercel يستقبل كل المسارات ويحوّلها لتطبيق الفرونت
إند، و**لا يوجد سيرفر Laravel منشور فعليًا**. لذلك تظهر المتاجر «جاري التحميل»
للأبد ولا يعمل تسجيل الدخول.

الحل — انشر الباك إند على استضافة PHP حقيقية (اختر ما يناسبك):

- VPS (أبسطها Hetzner/DigitalOcean) مع FrankenPHP أو Nginx+PHP-FPM، أو
- خدمة مدارة مثل Laravel Forge / Railway / Render.

ثم:

1. انسخ `backend/` إلى السيرفر، وثبّت الاعتماديات: `composer install --no-dev`.
2. انسخ `backend/.env.example` إلى `.env` واملأه (APP_KEY عبر
   `php artisan key:generate`، وDB_URL من خطوة 2، ومتغيرات Firebase وADMIN_EMAILS
   من خطوة 1).
3. شغّل `php artisan migrate --force` ثم `php artisan config:cache`.
4. اجعل الـ DocumentRoot يشير إلى `backend/public`.
5. وجّه مسار `/api` إلى السيرفر:
   - الأنضف: ارفع الباك إند على دومين فرعي مثل `api.ordarat.com` وعدّل
     `apiUrl` في ملفي environment بالفرونت إند إلى `https://api.ordarat.com/api`.
   - أو استخدم rewrite في Vercel يوجّه `/api/*` لسيرفر الباك إند (موضّح في
     `docs/BACKEND_DEPLOYMENT.md`).

---

## 4) إعادة بناء الفرونت إند ونشره

بعد ملء قيم Firebase الحقيقية في ملفي environment:

```bash
cd frontend
npm ci
npm run build
```

وانشر محتوى `dist/frontend/browser` على Vercel (أو استضافتك الحالية).

## قائمة التحقق بعد التفعيل (مرّ عليها واحدة واحدة)

- [ ] فتح الموقع → زر «كمل بجوجل» **مفعّل** وليس رماديًا.
- [ ] تسجيل الدخول بجوجل يعمل، وحساب جديد يُوجَّه تلقائيًا لصفحة الترحيب
      (اختيار: أطلب / عندي نشاط).
- [ ] اختيار «أطلب» يفتح نموذج العميل (اسم + موبايل مصري + الموقع)، وزر
      «كمّلها عند أول طلب» يتخطى النموذج، وعند إتمام طلب فعلي تُحفظ البيانات
      في الملف الشخصي.
- [ ] اختيار «عندي نشاط» يفتح نموذج النشاط (اسم، نوع: مطعم/بقالة، تليفون،
      منطقة داخل قنا، عنوان، فروع؟، الموقع) وبعد الإرسال تظهر صفحة الانتظار
      فيها رقم التواصل وزر واتساب.
- [ ] بحساب الأدمن: لوحة التحكم فيها تبويب «طلبات الانضمام» يعرض الطلب،
      والقبول ينشئ المتجر والفرع الرئيسي ويمنح دور التاجر من السيرفر، والرفض
      يتطلب سببًا.
- [ ] صفحة المتاجر تعرض المتاجر (تأكد أن `/api/stores` يعيد JSON وليس HTML:
      افتح الرابط مباشرة في المتصفح).
- [ ] إتمام طلب كاش يعمل ويظهر في صفحة تتبع الطلب وفي لوحة التاجر.

أي بند فشل: ارجع للخطوة المقابلة بالأعلى. أشهر سببين للفشل هما نسيان إضافة
الدومين في Authorized domains (خطوة 1-4) وبقاء `/api` محوّلًا للفرونت إند
بدل الباك إند (خطوة 3).
